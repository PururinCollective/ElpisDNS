ML-DSA-44: second in the world to validate it

ML-DSA-44 is the post-quantum signature NIST published as FIPS 204. ΕΛΠΙΣ Resolver checks it on DNSSEC answers — the second resolver in the world to do so, after Cloudflare — and it's on by default on every ΕΛΠΙΣ Resolver server we run.

In plain words

Three ideas, and you've got it.

DNSSEC signs the answers

A domain that uses DNSSEC signs its DNS records. A validating resolver checks the signature, so a forged answer is thrown away instead of reaching you.

Today's signatures won't last forever

RSA and elliptic-curve signatures could be broken by a large enough quantum computer. None exists yet — but the keys are public, and the internet changes slowly.

ML-DSA is built for what's next

It rests on lattice maths that quantum computers aren't known to speed up. It grew out of CRYSTALS-Dilithium, and NIST made it a standard in 2024.

Why start now

Resolvers have to go first

A DNSSEC public key sits in the DNS for anyone to read. Once a big enough quantum computer exists, someone could work out the matching private key from it and sign fake answers that look completely genuine.

The fix is new signatures, and a domain can only switch once the resolvers checking it understand them. Standards, software and zones each take years to move. So we built ML-DSA into ΕΛΠΙΣ Resolver now, long before anyone has to depend on it.

How ΕΛΠΙΣ Resolver checks it

No crypto library borrowed, and nothing skipped.

Written from the standard

The verifier follows FIPS 204 and is written from scratch in portable C99, in the same tree as the rest of the resolver. All three sizes are built in: ML-DSA-44, 65 and 87.

Tested on every build

The worked example from draft-westerbaan-dnssec-mldsa — key tag, DS digest and a real signature over an MX record — is checked every time the code is built, along with signatures that must be rejected.

Ready for big answers

One ML-DSA-44 signature is 2,420 bytes — more than the 1,232 bytes a UDP reply safely carries. ΕΛΠΙΣ Resolver retries over TCP when an answer is truncated, so large signed answers still arrive.

Same rules as every algorithm

If a signature doesn't check out, the answer is refused with SERVFAIL and an Extended DNS Error. A forged answer is never passed on to you.

ΕΛΠΙΣ Resolver validates every row of this table. An ML-DSA-44 signature is about 38 times the size of an ECDSA one — the price of being quantum-safe.

Where things stand

ML-DSA in DNSSEC is still early. The algorithm number 18 comes from draft-westerbaan-dnssec-mldsa and is what the public test zones sign with, but IANA hasn't made it final. ML-DSA-65 and 87 don't have numbers yet at all.

So today, ML-DSA-44 validation protects those test zones, while the rest of the internet keeps using RSA, ECDSA and Ed25519 — which ΕΛΠΙΣ checks too. When the numbers are settled it's a one-line change, not a new build.

Running your own?

It's already on. These are the defaults in elpis.conf:

dnssec: yes
mldsa44-algorithm: 18
mldsa65-algorithm: 25    # placeholder
mldsa87-algorithm: 26    # placeholder

The status page's About window shows each ML-DSA size as active or available.

Questions

What is ML-DSA-44?

The smallest of the three parameter sets of ML-DSA, the Module-Lattice-Based Digital Signature Algorithm that NIST published as FIPS 204 in 2024. It grew out of CRYSTALS-Dilithium and is designed to stay secure even against a large quantum computer.

Which DNS resolvers validate ML-DSA-44?

Cloudflare was first. ΕΛΠΙΣ Resolver is the second in the world, and it's open source, so anyone can run it.

Do I need to change anything to use it?

No. ML-DSA-44 validation is on by default in ΕΛΠΙΣ Resolver, alongside RSA, ECDSA and Ed25519, and ΕΛΠΙΣ Resolver is what answers ΕΛΠΙΣ DNS. Only the two PowerDNS standby backups don't check it.

Can a quantum computer break DNS today?

No. No quantum computer today can break RSA or ECDSA. Starting early matters because resolvers must understand a new algorithm before any domain can safely switch to it, and that takes years.

Which DNSSEC algorithm number does ML-DSA-44 use?

18, as proposed in draft-westerbaan-dnssec-mldsa and used by the public test zones. IANA hasn't made it final yet, so ΕΛΠΙΣ Resolver keeps it as a one-line setting.
