Android 9 and newer DoT

The easiest one. Android calls it Private DNS: it covers every app, on Wi-Fi and mobile data alike.

  1. Open Settings → Network & internet → Private DNS. On Samsung: Connections → More connection settings.
  2. Choose Private DNS provider hostname.
  3. Enter the hostname only — no https://, no tls://:
b.hitoha.moe
  1. Tap Save. If it won't connect, the network may be blocking port 853 — try another network.

Windows 11 DoH

Windows wants an IP address and the DoH address. Find the IP first: 

nslookup b.hitoha.moe
  1. Settings → Network & internet → your Wi-Fi or Ethernet → Hardware properties.
  2. Next to DNS server assignment, click Edit and choose Manual.
  3. Turn on IPv4 and paste the IP from nslookup into Preferred DNS.
  4. Set DNS over HTTPS to On (manual template) and paste:
https://b.hitoha.moe/dns-query
  1. Leave Fallback to plaintext off, then save. Repeat for IPv6 if your address supports it.
Windows 10 has no setting for this. Use an app like YogaDNS or dnscrypt-proxy, or set it on your router so every device gets it.

iOS, iPadOS and macOS DoH / DoT

Apple supports encrypted DNS, but only through an app or a configuration profile — there's no text box in Settings.

  1. Install a DNS app from the App Store: AdGuard, DNSecure or DNSCloak all take a custom server.
  2. Add a custom server and paste:
https://b.hitoha.moe/dns-query
  1. Turn it on, then check Settings → General → VPN & Device Management → DNS shows it as active.
  2. On a Mac, open the .mobileconfig profile and approve it in System Settings → Privacy & Security → Profiles.

Firefox DoH

This covers Firefox only. Other apps on the device keep using the system setting.

  1. Settings → Privacy & Security → scroll to DNS over HTTPS.
  2. Choose Max Protection, pick Custom as the provider, and paste:
https://b.hitoha.moe/dns-query
  1. Check about:networking#dns — the TRR column should say true.

Chrome, Edge, Brave, Vivaldi DoH

  1. Open chrome://settings/security (Edge: edge://settings/privacy).
  2. Turn on Use secure DNS, choose Custom, and paste:
https://b.hitoha.moe/dns-query

MikroTik RouterOS DoH

Set it on the router and every device at home is covered — even the ones with no settings screen. The MikroTik button on the home page downloads a ready-made script; the manual way is below.

1. Give the router a DNS server to start with

/ip dns
set servers=1.0.0.1,1.1.1.1 allow-remote-requests=yes

2. Import certificates so DoH can verify

/tool fetch url="https://curl.se/ca/cacert.pem"
/certificate import file-name=cacert.pem passphrase=""

3. Pin the address, then switch DoH on

/ip dns static
add name="b.hitoha.moe" type=A address=151.158.198.53

/ip dns
set use-doh-server="https://b.hitoha.moe/dns-query" verify-doh-cert=yes
Use the IP that nslookup gives for your hostname. Without that static entry the router can't find the server it's about to rely on.

RouterOS 7.20 and later: forwarders

/ip dns forwarders
add name=ELPIS doh-servers="https://b.hitoha.moe/dns-query"

/ip dns static
add name=* forward-to=ELPIS type=FWD

OpenWrt DoH

  1. Install the DoH proxy and its web page:
opkg update
opkg install https-dns-proxy luci-app-https-dns-proxy
  1. Point it at your address:
uci set https-dns-proxy.@https-dns-proxy[0].resolver_url='https://b.hitoha.moe/dns-query'
uci set https-dns-proxy.@https-dns-proxy[0].bootstrap_dns='1.1.1.1,1.0.0.1'
uci set https-dns-proxy.@https-dns-proxy[0].listen_addr='127.0.0.1'
uci set https-dns-proxy.@https-dns-proxy[0].listen_port='5053'
uci commit https-dns-proxy
/etc/init.d/https-dns-proxy restart
  1. Send all lookups through it, and ignore the ISP's DNS:
uci -q delete dhcp.@dnsmasq[0].server
uci add_list dhcp.@dnsmasq[0].server='127.0.0.1#5053'
uci set dhcp.@dnsmasq[0].noresolv='1'
uci commit dhcp
/etc/init.d/dnsmasq restart

AdGuard Home & Pi-hole Upstream

Already running your own filter? Keep it — and use ΕΛΠΙΣ Resolver as its upstream instead of Google or Cloudflare. Your blocklists, logs and rules stay on your hardware; we just do the lookups, straight from the root servers.

AdGuard Home

  1. Open Settings → DNS settings, and replace everything in Upstream DNS servers with the list above.
  2. Set Upstream mode to Load-balancing. It asks the fastest server and moves on if one stops answering. Parallel requests asks every server at once — fine with one address family, but with IPv6 + IPv4 each server gets every question twice.
  3. Optional: paste the backup list into Fallback DNS servers.
  4. Press Test upstreams, then Apply.

Pi-hole

  1. Switch the list above to Pi-hole — it writes IPv4 ports the Pi-hole way, like 151.158.198.49#5301.
  2. Open Settings → DNS, untick the built-in providers, and paste into Custom DNS servers.
  3. Save.
Prefer our filtering too? Use your encrypted address from the home page as the upstream instead — https://b.hitoha.moe/dns-query — and add the IPv6 resolver addresses above as Bootstrap DNS servers so AdGuard can find it on a cold start.

Check it works

  1. Make sure names still load:
nslookup example.com
  1. Check filtering is on — a known ad domain should come back empty or as 0.0.0.0.
  2. Run dnscheck.tools or dnsleaktest.com. If your internet provider shows up, something is bypassing the setting.
Encrypted DNS hides which names you look up from everyone between you and us. It isn't a VPN: it doesn't hide the sites you then connect to, and it won't make you anonymous.

If something's not right

  1. Nothing loads. Your device can't find our server's name. Add a bootstrap address or a static entry for the hostname.
  2. Android won't accept the hostname. Port 853 is blocked on that network. Try another network, or use DoH elsewhere.
  3. Certificate errors on a router. The certificates are missing or the clock is wrong. Import them and fix NTP.
  4. Works, then stops. Something is intercepting port 53. Turn off plaintext fallback.
  5. Still stuck? Ask on Discord or open an issue on GitHub with your address, your device and the exact error.
