How to use them

AdGuard Home & Pi-hole

Two minutes, and every device behind your filter gets our recursion and DNSSEC.

AdGuard Home

  1. Go to Settings → DNS settings → Upstream DNS servers.
  2. Paste the addresses, one per line. Ports go after a colon.
2402:4e20:c0de::b00b
2402:4e20:b00b::1001
2a0f:1cc6:bab1::1111
151.158.198.47
151.158.198.49:5301
  1. Pick Parallel requests, so the fastest answer wins.
  2. Put the same addresses in Bootstrap DNS servers, then Apply.

Pi-hole

  1. Go to Settings → DNS and untick the built-in providers.
  2. Add ours under Custom DNS servers. Pi-hole writes the port after a #.
2402:4e20:c0de::b00b
2402:4e20:b00b::1001
151.158.198.47
151.158.198.49#5301
  1. Save. Then run a test on dnscheck.tools: you should see DNSSEC passing and one of our networks answering, not your ISP.
Mix servers from different groups, like one Fizo, one Sakurako and one Kevin. They sit on different machines, so one going down for an upgrade never takes your DNS with it. In Indonesia, add Ryukura in Jakarta: it's the closest to you.

New in 2.5.0 · Erdentempel

Refused at the door

A resolver open to the public is also asked for names whose only purpose is to make it work: random labels under a domain someone is flooding, and big signed answers aimed at a spoofed address. ΕΛΠΙΣ Resolver now knows them, and turns them away before it even looks at the cache.

How the gate works

  1. The names come from the ElpisDNS honeypot, which sees the abuse first, and are compiled into the binary.
  2. Every question is checked: a name on the list, or any name below it, over UDP or TCP, of any type.
  3. A match gets REFUSED with EDE 15 (Blocked), before the cache is looked at. Nothing is resolved for it.
  4. The check is one hash per label, about 20 ns whether it matches or not, so a longer list costs nothing more.

A gate, not a filter

It isn't an ad blocker. Eleven names, none of them a site anyone visits, so your AdGuard Home or Pi-hole still makes every call that matters to you.

What it saves is real. Each random label is a cache miss and a full resolution of its own, and each spoofed question sends a big answer to someone who never asked. Refused early, they cost almost nothing, and the resolver is nobody's weapon.

The status page counts them as blocked. Only the name the client asks is checked, never a CNAME target.

Running your own? The gate is on by default, and blocklist: no in elpis.conf switches it off. 2.5.0 also makes elpis -t fail a config with a bad value in it instead of calling it OK, so an update never restarts onto one. No config that worked stops working. Release notes.

Since 2.4.0 · ADoX

Encrypted past us, too

DoH and DoT encrypt the trip from you to us. ADoX covers the next one: ΕΛΠΙΣ Resolver now asks the root, the TLDs and each domain's name server over DNS over TLS, wherever they take it.

How it works

  1. The first question to a name server goes plain, as always, with a copy over TLS on port 853. Nobody waits on the copy, so it costs no time.
  2. The server answers over TLS? From then on it gets every question over TLS only, on a connection kept open.
  3. It doesn't? It gets plain DNS as before, and we try TLS again every hour.
  4. Servers that take TLS are asked first, so fewer of your names cross the wire in the clear.
  5. Each question is padded to 128 bytes, so its length gives less away.

What it stops, and what it doesn't

It stops anyone watching the path, like the networks between us and the name server, from reading what we ask. It can't stop someone sitting on the path, who could block port 853 and send us back to plain DNS, which is where we were before.

The name server still sees the question; it has to, to answer it. And DNSSEC checks every answer the same way, however it arrived.

Few name servers take TLS yet. b.root-servers.net and Facebook's do, and more will as their operators turn it on.

See it yourself. Use ΕΛΠΙΣ as your DNS and open dnscheck.tools: ADoX in the bottom bar means our resolver reached its test server over TLS. Running your own? Add authoritative-dot: opportunistic to elpis.conf. It's off by default, and the configuration guide has the details.
